# ჭორაობა

ანონიმური, ქართულენოვანი სოციალური სივრცე პოსტებისთვის, ფოტოების გაზიარებისა და კომენტარებისთვის.

## პირდაპირ გამოყენება

გახსენი `index.html` ბრაუზერში. შეგიძლია ფოტოს ატვირთვა, პოსტის გამოქვეყნება, კომენტარის დაწერა და წაშლა. ეს ვერსია მონაცემებს მხოლოდ იმავე ბრაუზერის IndexedDB-ში ინახავს; სხვა მომხმარებლები ამ პოსტებს ვერ ნახავენ.

## საერთო ონლაინ ვერსია

სხვა მომხმარებლებთან საერთო ლენტისთვის საჭიროა Node.js 20 ან უფრო ახალი და Supabase პროექტი.

1. დააინსტალირეთ დამოკიდებულებები: `npm install`
2. Supabase SQL Editor-ში გაუშვით `supabase/migrations/202611030001_initial_schema.sql`.
3. დააკოპირეთ `.env.example` როგორც `.env.local` და მიუთითეთ Supabase project URL და publishable/anon key.
4. გაუშვით `npm run dev` და გახსენით `http://localhost:5173/online.html`.

`npm run build` ამზადებს ლოკალურ და საერთო ონლაინ ვერსიებს.

## ადმინისტრატორი

შექმენით და ელფოსტით დაადასტურეთ ადმინისტრატორის ანგარიში. შემდეგ Supabase SQL Editor-ში, მხოლოდ პროექტის მფლობელის ანგარიშით, გაუშვით:

```sql
insert into public.admin_users (user_id)
select id from auth.users where email = 'admin@example.com';
```

`admin@example.com` შეცვალეთ თქვენივე ანგარიშის ელფოსტით. ადმინისტრატორის როლი client-იდან ვერ მიენიჭება. მოდერაციის გვერდი აჩვენებს საჩივრის ობიექტის ანგარიშის UUID-ს; რეალური პიროვნების დადგენა UUID-ით შეუძლებელია. საჯარო API-ით მომხმარებლის ელფოსტას არ ვამხელთ.

## კონფიდენციალურობა და უსაფრთხოება

- ონლაინ ვერსიაში პოსტებსა და კომენტარებში ავტორი ყოველთვის „ანონიმად“ ჩანს. ანგარიშის ელფოსტა და UUID საჯარო ინტერფეისში არ იბეჭდება.
- PostgreSQL-ის RLS პოლიტიკები ზღუდავს ჩაწერას ავტორით, ხოლო წაშლას ავტორით ან მოდერატორით. საჩივრებსა და შეზღუდულ ანგარიშებზე მხოლოდ მოდერატორს აქვს წვდომა.
- ადმინისტრატორი ხედავს შიდა ანგარიშის UUID-ს, რათა განმეორებითი დარღვევები შეამოწმოს; ეს ფსევდონიმურობას უზრუნველყოფს, არა რეალური პიროვნების გარანტირებულ ანონიმურობას.
- ონლაინ ვერსიის ფოტოების საცავი საჯაროდ წაკითხვადია, რადგან პოსტები ყველასთვის ჩანს. ატვირთვა შეზღუდულია ავტორიზებული მომხმარებლით, სურათის MIME ტიპებითა და 10 მბ ზომით.
- საჯარო frontend-ში გამოიყენება მხოლოდ Supabase publishable/anon key. Service-role გასაღები ბრაუზერში არ ჩასვათ.
- `blocked_users` ახალი პოსტების, კომენტარებისა და სურათების ატვირთვას ბლოკავს. უკვე არსებული ანგარიშის სესია რჩება, მაგრამ შინაარსის შექმნა აღარ შეუძლია.

## რეალური გამოყენებისთვის

Supabase Dashboard-ში ჩართეთ ელფოსტით დადასტურება და განსაზღვრეთ შესაბამისი rate limit-ები. დაამატეთ CAPTCHA/anti-spam, ანგარიშის წაშლის პროცესი, კონფიდენციალურობის პირობები, სარეზერვო ასლები და საჩივრების მონიტორინგი. ონლაინ ვერსიის მონაცემთა ბაზა და ფოტოების საცავი თქვენს Supabase პროექტზეა დამოკიდებული.
